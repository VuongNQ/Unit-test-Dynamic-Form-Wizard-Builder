# Dynamic Form Wizard Builder — Copilot Instructions

## Project Overview

This is a React 19 + TypeScript 6 + Vite project implementing a dynamic form wizard with two independent workflows:
- **Onboarding**: 3-step company setup
- **Loyalty**: 7-step loyalty program onboarding (new)

Both use a shared `FormWizard` orchestrator with route-specific configs from i18n.

---

## Tech Stack & Standards

### Core Dependencies
- **React 19** (function components only)
- **TypeScript 6** (strict mode, no `any`)
- **Vite 8** + **Vitest 4** (testing)
- **react-hook-form 7** + **zodResolver** (form state & validation)
- **Zod 4** (config & form schemas)
- **@tanstack/react-query 5** (server state)
- **CSS Modules** (no Tailwind)

### Code Conventions
- **Named exports only** — never default-export components
- **`type` aliases, not `interface`** — use `type Props = {...}`
- **`import type`** for all type-only imports
- **Types from `z.infer<>`** — no hand-written interfaces for data shapes
- **No `any`** — use `unknown` where truly unknown
- **Accessibility first**: every input has `id` + matching `<label htmlFor={id}>`

## OnboardingLoyalty Module — Testing Instructions

### Purpose

The `OnboardingLoyalty` module manages route-level workflow composition for two independent wizard flows:

1. **Onboarding (`/onboarding`)** — 3-step company setup wizard
2. **Loyalty (`/loyalty`)** — 7-step loyalty program onboarding (new)

Each route loads its own validated wizard config via React Query and passes it to the shared `FormWizard` orchestrator.

---

### Loyalty Wizard Config (7 Steps)

| Step | Title | Field | Input Type |
|------|-------|-------|-----------|
| 1 | Primary objective | `primaryObjective` | radio (5 options) |
| 2 | Industry | `industry` | radio (11 options) |
| 3 | Target region | `targetRegion` | radio (8 options) |
| 4 | Monthly revenue | `monthlyRevenue` | radio (4 options) |
| 5 | Loyalty budget % | `loyaltyBudgetPercentage` | radio (6 options) |
| 6 | Rules & Redemptions | `earningRule_*`, `redemption_*` | 6 checkboxes (pre-checked) |
| 7 | Suggested plan | _(no input)_ | summary step |

**Config source:** `src/i18n/locales/en.json` → `loyaltyConfig`  
**Validator:** `getValidatedLoyaltyWizardConfig()`

### Testing Patterns

#### Query by Locale Text

All UI text comes from `en.json`. Query using translated text:

```typescript
// Step title
expect(screen.getByText(/What is your primary objective/i)).toBeInTheDocument()

// Radio option (locale key: loyalty.optionLabels.clv)
screen.getByRole('radio', { name: /Increase Customer Lifetime Value/i })

// Checkbox (locale key: loyalty.fieldLabels.earningRule_happyBirthday)
screen.getByRole('checkbox', { name: /Happy birthday/i })
```

#### User Interaction

```typescript
// Click radio
const radio = await screen.findByRole('radio', { name: /CLV/i })
await user.click(radio)
expect((radio as HTMLInputElement).checked).toBe(true)

// Navigate
await user.click(screen.getByRole('button', { name: 'Next' }))      // forward
await user.click(screen.getByRole('button', { name: 'Back' }))      // backward
await user.click(screen.getByRole('button', { name: 'Submit' }))    // last step
```

#### State Preservation (Back Navigation)

Radio/checkbox selections persist due to `react-hook-form` state preservation (`shouldUnregister: false`):

```typescript
// Select on step 1
const radio = await screen.findByRole('radio', { name: /CLV/i })
await user.click(radio)

// Navigate forward, then back
await user.click(screen.getByRole('button', { name: 'Next' }))
// ... navigate further ...
await user.click(screen.getByRole('button', { name: 'Back' }))

// Selection is preserved
expect((radio as HTMLInputElement).checked).toBe(true)
```

### Test Scenarios

**Scenario A — Happy Path (7 Steps)**
- Navigate all 7 steps: objective → industry → region → revenue → budget → rules → plan
- Verify radio selections persist
- Verify pre-checked earning rules and redemptions

**Scenario C — Back Navigation**
- Fill steps 1, 2, 3 → click Back twice
- Verify prior selections (steps 1 & 2) still checked

**Scenario D — Back Button Disabled**
- On first step, Back button must be disabled

**Scenario E — Onboarding Unchanged**
- `/onboarding` route still shows 3-step flow (Company Setup, Business Details, Review & Consent)

**Scenario F — Route Separation**
- Loyalty state doesn't leak to onboarding
- Each route's `useQuery` with distinct `queryKey` loads fresh config + form state

### Common Issues

**Radio not found**
- Verify locale key in `en.json` matches displayed text
- Radio labels are translated at render time via `t(option.label)`

**State not preserved after Back**
- Verify `shouldUnregister: false` in `useForm()` config in `FormWizard.tsx`

**Checkboxes not pre-checked**
- Verify `defaultValues` in `FormWizard.tsx` includes `earningRule_happyBirthday: true`, etc.

## Config Validation

Both wizard configs are validated at module scope using `wizardConfigSchema.parse()`:

```typescript
const parsedLoyaltyConfig = wizardConfigSchema.parse(getLoyaltyWizardConfig())
expect(parsedLoyaltyConfig.steps.length).toBe(7)
```

**No mocking** of `wizardConfigSchema` or `react-hook-form` — tests use real implementations.

## Schema & Field Types

### Discriminated Union: `fieldSchema`

```typescript
// wizardConfig.ts
export const fieldSchema = z.discriminatedUnion('type', [
  textFieldSchema,      // { type: 'text' | 'date', placeholder?, ... }
```

## Key Implementation Notes

1. **Radio field type** is a new discriminated union member in `wizardConfig.ts`
2. **Loyalty config** is separate from onboarding config in `en.json` (`loyaltyConfig` namespace)
3. **Loyalty form fields** are all optional in `formSchema` — step-level `trigger()` handles required-ness
4. **Pre-selected defaults** in `FormWizard.tsx`: earning rules (birthday, review) and all redemptions default to `true`
5. **State preservation** relies on `shouldUnregister: false` in `useForm()` config
6. **Route separation** via distinct `queryKey` in React Query — each route loads its own config independently
